# Продукт и границы MVP

## Цель

CreatorHire — закрытый Telegram-маркетплейс вакансий и специалистов в creator-management. Продукт предназначен только для лиц 18+ и поддерживает только законную деятельность. Он не предназначен для распространения adult-контента, принуждения, торговли людьми или обхода законов.

## Граница текущего этапа

Сейчас реализован только onboarding. Он создаёт минимальный профиль кандидата или агентства, но не включает вакансии, резюме, поиск, отклики, контакты, модерацию или любые экраны дальнейшего продукта. Специализации текущего onboarding: chatter, chatter team lead и recruiter.

В будущих этапах кандидат сможет работать с профессиональным профилем, а агентство — с командным аккаунтом. Эти возможности не являются частью текущей реализации и не должны появляться в UI или API до отдельного продуктового решения.

## Первый реализованный сценарий — onboarding

Первый пользовательский сценарий ограничен регистрационным wizard и не включает вакансии, резюме или поиск. Цель UX — завершение менее чем за 40 секунд: один вопрос на экран, крупные touch-targets, автоматический переход после выбора и короткий прогресс.

**Кандидат:** приветствие → роль → специализация → опыт → английский → часовой пояс → минимальная зарплата в USD/месяц → готово.

**Агентство:** приветствие → роль → название → размер команды → ежемесячный найм → готово.

Выборы сохраняются после каждого шага. У завершившего пользователя wizard больше не показывается; в локальном режиме разработки доступен явный сброс onboarding. В production пользователь определяется только по серверно проверенному Telegram `initData`; локальный режим использует один фиксированный development account и не принимает user ID от клиента.

## Не входит в MVP

Встроенный чат, AI matching/скоринг, видеозвонки, escrow, переводы, криптовалютные функции, публичные чёрные списки, пользовательский adult-контент, отзывы и парсинг переписок Telegram.

## Риски и недостающие решения

1. **Юрисдикция и допустимость бизнеса.** До запуска нужны юрист, политика допустимых вакансий, список запрещённых практик, страны запуска, процедура проверки возраста и DPA с подрядчиками. Шаблонные страницы не являются юридическими документами.
2. **Возраст.** Самоутверждение 18+ — слабая проверка. Для MVP это осознанная продуктовая граница; до масштабирования нужно выбрать провайдера/процедуру возрастной верификации с минимизацией данных.
3. **Безопасность кандидатов.** Нужны лимиты поиска/приглашений, обнаружение выгрузок, аудит раскрытия контакта, жалобы, модерация и блокировки. Ни один клиентский фильтр не считается защитой.
4. **Модель занятости.** Нужно согласовать валюты, диапазоны оплат, типы выплат, часовые пояса, занятость и допустимые форматы тестовых заданий. На старте это справочники и структурированные поля, не свободный текст.
5. **Командные аккаунты.** Агентство может иметь несколько рекрутеров; права должны быть scoped к `agency_id`, а не только к глобальной роли.
6. **Уведомления.** Требуются тексты, opt-in/настройки и обработка неудачной отправки ботом. Уведомления — асинхронный outbox, а не побочный эффект HTTP-запроса.
7. **Модерация.** До beta нужно утвердить SLA, причины решений, апелляции и правила хранения доказательств.

## Метрики для последующего согласования

Активированные кандидаты и агентства, опубликованные вакансии, доля откликов с ответом, время до первого контакта, качество жалоб/блокировок, раскрытия контактов, конверсия в найм. Метрики не должны включать сырой PII или Telegram `initData`.
