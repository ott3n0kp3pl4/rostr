# Роли и права

Этот документ разделяет существующие поля onboarding и будущую систему авторизации. Он не описывает production-ready RBAC.

## Implemented

- Onboarding сохраняет тип пользователя: `CANDIDATE` или `AGENCY_OWNER`.
- Серверный onboarding service сверяет выбранный тип с ожидаемым шагом wizard; это предотвращает переход между ветками кандидата и агентства в текущем сценарии.
- При создании агентства создаётся его первый `AgencyMember` с ролью `OWNER`.

Это минимальные проверки потока onboarding, а не универсальная авторизация ресурсов.

## Partially implemented

`AgencyMember` уже содержит enum `OWNER | RECRUITER`, но UI и API пока не позволяют добавлять участников. Нет проверки прав рекрутера, управления участниками или agency-scoped доступа к каким-либо ресурсам.

`UserStatus` хранится в базе для будущих состояний, но статус не образует модерационную систему и не применяется как общий access-control механизм.

## Approved but not implemented

Для следующих продуктовых этапов одобрена модель: сервер проверяет permission и scope, а не имя роли в UI. Для неё потребуются таблицы roles/permissions, server-side policy layer и тесты на IDOR.

Планируемые роли и scope:

| Роль             | Планируемый scope        | Статус                                                             |
| ---------------- | ------------------------ | ------------------------------------------------------------------ |
| candidate        | собственный пользователь | Текущий onboarding type; продуктовые permissions не реализованы.   |
| agency_owner     | конкретное агентство     | Текущий onboarding type; agency-scoped permissions не реализованы. |
| agency_recruiter | назначенное агентство    | Не реализовано.                                                    |
| moderator        | platform                 | Не реализовано.                                                    |
| admin            | platform                 | Не реализовано.                                                    |

Планируемый vocabulary включает `candidate.profile.*`, `vacancy.*`, `candidate.search:agency`, `contact.disclose:agency`, `moderation.review` и `billing.manage:agency`. Эти строки не являются действующими правами и не должны использоваться как основание для доступа.

## Proposed

Для опасных операций предполагаются явная причина действия, аудит и двухэтапное подтверждение массовых или необратимых изменений. Решение о конкретных permission и scope фиксируется отдельным ADR перед реализацией.

## Unresolved

- Набор ресурсов и permissions для первого этапа после onboarding.
- Процесс назначения platform-ролей и разделение обязанностей moderator/admin.
- Политика отзыва agency membership и поведения при блокировке пользователя.
